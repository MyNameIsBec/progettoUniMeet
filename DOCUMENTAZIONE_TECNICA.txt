1. ORGANIZZAZIONE DEL PROGETTO
================================================================================

Il progetto e suddiviso in due parti principali:

  pg_backend/   - Backend Node.js + Express + Prisma (PostgreSQL)
  pg_frontend/  - Frontend Ionic 8 + Angular 19 + Leaflet


Struttura directory:

  progettoUniMeet/
  +-- pg_backend/
  |   +-- src/
  |   |   +-- server.ts              # Entry point, Express + Swagger
  |   |   +-- app.ts                 # Middleware routing
  |   |   +-- routes/                # Endpoint REST
  |   |   +-- services/              # Logica di business
  |   |   +-- middleware/             # Auth, upload
  |   |   +-- validators/            # Validazione input (Zod)
  |   |   +-- prisma/                # Schema DB + migrations
  |   +-- uploads/                   # File caricati
  |   +-- swagger.json               # Generato automaticamente all'avvio
  |
  +-- pg_frontend/
  |   +-- src/
  |   |   +-- app/
  |   |   |   +-- core/
  |   |   |   |   +-- models/interfacce.ts     # Interfacce TypeScript
  |   |   |   |   +-- services/                # Servizi HTTP
  |   |   |   |   +-- guards/                  # Route guards
  |   |   |   +-- components/
  |   |   |   |   +-- sidebar/                 # Sidebar navigazione
  |   |   |   |   +-- dashboard-layout/        # Layout pagine autenticate
  |   |   |   +-- features/
  |   |   |       +-- auth/          # Login, registrazione, recupero password
  |   |   |       +-- studente/      # Dashboard, prenota, dettaglio, bacheca
  |   |   |       +-- docente/       # Dashboard, gestione-slot, dettaglio
  |   |   +-- theme/variables.scss   # Tema chiaro/scuro
  |   |   +-- global.scss            # Stili globali
  |   +-- angular.json

2. COMANDI DI AVVIO
================================================================================

Prerequisiti:
  - Node.js >= 18
  - PostgreSQL con database 'unimeet_db' creato


Backend:

  cd pg_backend

  npm install                       # Installa dipendenze
  npx prisma generate               # Genera client Prisma
  npx prisma migrate dev            # Esegui migrazioni DB
  npx prisma studio                 # (Opzionale) GUI Prisma Studio

  npm run dev                       # Avvio sviluppo (nodemon, ricarica auto)
  npm start                         # Avvio produzione

  Il backend parte su http://localhost:5000
  Swagger UI su http://localhost:5000/api-docs


Frontend:

  cd pg_frontend

  npm install                       # Installa dipendenze

  ionic serve                       # Avvio sviluppo (ricarica auto)
  npx ng serve                      # Avvio sviluppo alternativo
  npx ng build --configuration production   # Build produzione
  npx ng build --configuration development  # Build sviluppo

  Il frontend parte su http://localhost:8100

4. REGOLE E CONVENZIONI
================================================================================

4.1 Registrazione
  - Password: almeno 8 caratteri (validato lato backend con Zod)
  - Email: unica nel sistema (vincolo UNIQUE su DB)
  - Studente creato con stato IN_ATTESA fino a conferma admin
  - Validazione sia lato frontend (form) che backend (Zod)

4.2 Stato prenotazioni
  Varianti valide (case-sensitive, backend forza uppercase):
    IN_ATTESA     - appena creata
    CONFERMATA    - accettata dal docente
    COMPLETATA    - ricevimento svolto
    ANNULLATA     - cancellata
    RIFIUTATA     - respinta dal docente

  NON usare varianti come: annullato, completato, in-attesa, confermato.

4.3 URL / API
  - Backend:  http://localhost:5000/api/...
  - Swagger:  http://localhost:5000/api-docs
  - Route raggruppate per entita (/api/auth, /api/docenti, ...)

4.4 Frontend - naming
  - Feature pages:  features/<ruolo>/<nome-feature>/
  - Componenti:     components/
  - Servizi:        core/services/
  - Modelli:        core/models/

4.5 Mappa Leaflet
  - Leaflet importato come CommonJS (allowedCommonJsDependencies in angular.json)
  - Icone default sostituite con L.divIcon personalizzati
  - Chiamare invalidateSize() dopo apertura in modal o cambio viewport

4.6 CSS e dark mode
  - Stili specifici nel .scss del componente (non global.scss)
  - Dark mode: :host-context(body.dark) .classe { ... }
  - Usare variabili CSS Ionic (var(--ion-card-background), var(--ion-text-color))

6. SCHEMA DEL DATABASE (PRISMA)
================================================================================

File: pg_backend/prisma/schema.prisma

Modelli principali:

  CorsoDiStudi
    id_corso_di_studi (String, PK)
    nome               (String, UNIQUE)
    -> relaziona con: Studente, DocenteCorsoDiStudi, Bacheca, Corso

  Studente
    matricola (String, PK)
    nome, cognome, email (UNIQUE), password
    id_corso_di_studi (FK -> CorsoDiStudi)
    -> relaziona con: Prenotazione, Segnalazione

  Docente
    id_docente (String, PK)
    nome, cognome, email (UNIQUE), password, ufficio
    -> relaziona con: Corso, SlotRicevimento, DocenteCorsoDiStudi, FAQ, Segnalazione

  Amministratore
    id_admin (String, PK)
    nome, email (UNIQUE), password

  Corso
    id_corso (String, PK)
    nome_corso, anno, cfu
    id_docente (FK -> Docente)
    id_corso_di_studi (FK -> CorsoDiStudi, optional)
    -> relaziona con: Bacheca (1-to-1)

  SlotRicevimento
    id_slot (String, PK)
    data, ora_inizio, ora_fine, disponibilita
    id_docente (FK -> Docente)
    -> relaziona con: LuogoRicevimento (1-to-1), Prenotazione

  LuogoRicevimento
    id_luogo (String, PK)
    nome_aula, edificio, piano
    latitudine (Float?, nullable), longitudine (Float?, nullable)
    id_slot (FK -> SlotRicevimento, UNIQUE)

  Prenotazione
    id_prenotazione (String, PK)
    data_prenotazione, argomento, descrizione?
    stato_prenotazione (String: IN_ATTESA/CONFERMATA/...)
    matricola_studente (FK -> Studente)
    id_slot (FK -> SlotRicevimento)
    -> relaziona con: Documento

  Documento
    id_documento (String, PK)
    nome_file, tipo_file, dimensione, percorso_file
    id_prenotazione (FK -> Prenotazione)

  Bacheca
    id_bacheca (String, PK)
    titolo, descrizione
    id_corso_di_studi (FK -> CorsoDiStudi)
    id_corso (FK -> Corso, UNIQUE)
    -> relaziona con: FAQ

  FAQ
    id_faq (String, PK)
    domanda, risposta
    id_bacheca (FK -> Bacheca)
    id_docente (FK -> Docente, optional)

  Segnalazione, Notifica, GiornoBloccato, CodiceVerifica
    (modelli ancillari per malfunzionamenti, notifiche, giorni festivi, reset password)


Relazioni chiave:
  - Docente <-> CorsoDiStudi: molti-a-molti tramite DocenteCorsoDiStudi
  - SlotRicevimento -> LuogoRicevimento: uno-a-uno
  - Corso -> Bacheca: uno-a-uno
  - Prenotazione -> Documento: uno-a-molti

Vincoli univocita:
  - email unica per Studente, Docente, Amministratore
  - data unica in GiornoBloccato
  - nome unico in CorsoDiStudi
  - id_corso unico in Bacheca
  - id_slot unico in LuogoRicevimento

8. FLUSSO DI AUTENTICAZIONE
================================================================================

1. Login: POST /auth/login -> riceve { accessToken, refreshToken, utente }
2. Frontend salva token in localStorage (chiave access_token)
3. Ogni richiesta autenticata include:
     Authorization: Bearer <accessToken>
4. Middleware JWT (middleware/auth.ts) verifica token su ogni richiesta
5. Allo scadere dell'access token (15 min):
     POST /auth/refresh -> nuovo access token
6. Logout: cancella token da localStorage, reindirizza a /login

Protezione route:
  - auth.guard.ts        -> blocca pagine senza token valido
  - role.guard.ts        -> verifica ruolo (studente/docente/admin)
  - Backend verifica ruolo tramite JWT payload

13. RISOLUZIONE PROBLEMI COMUNI
================================================================================

  Porta 5000 gia in uso:
    netstat -ano | findstr :5000
    taskkill /PID <id> /F

  DATABASE_URL non trovata (Prisma):
    Copiare .env.example in .env e configurare i valori

  CORS error:
    Verificare environment.ts punti a http://localhost:5000

  Swagger non carica:
    Riavviare il backend (npm run dev), rigenera swagger.json

  Leaflet module not found:
    npm install in pg_frontend

  401 Unauthorized:
    Rifare login o verificare Authorization header

  Mappa Leaflet invisibile:
    Chiamare map.invalidateSize() dopo aver reso visibile il container

  Relazione database mancante:
    npx prisma migrate dev

  Upload file troppo grande:
    Modificare limit in middleware/upload.ts

16. MIDDLEWARE BACKEND

File: pg_backend/src/middleware/

    Usato su tutte le route protette

  upload.ts
    Configura multer per upload file

  adminAuth.ts

    Usato su route /admin/*


================================================================================
17. GUARD FRONTEND
================================================================================

File: pg_frontend/src/app/core/guards/

  auth-guard.ts
    Export: authGuard (CanActivateFn)
    Logica: se authService.isLoggedIn() -> true
            altrimenti -> redirect a /login -> false

  role-guard.ts
    Export: roleGuard(ruolo: string) -> CanActivateFn
    Logica: se authService.hasRole(ruolo) -> true
            altrimenti -> redirect a /login -> false

  authService.isLoggedIn():
    Controlla presenza di access_token in localStorage

  authService.hasRole(ruolo):
    Confronta ruolo dal token decodificato con ruolo richiesto

19. GESTIONE FILE E UPLOAD
================================================================================

Percorso file caricati:
  pg_backend/uploads/

Middleware:
  pg_backend/src/middleware/upload.ts (multer)

Flusso:
  1. Frontend seleziona file (input type="file")
  2. POST /prenotazioni/:id/documenti con FormData
  3. Multer salva file in uploads/ con nome: <timestamp>-<originale>
  4. Backend crea record Documento nel DB con percorso_file
  5. File serviti staticamente da Express (express.static)

Accesso documenti:
  GET /uploads/<nomefile> (pubblico)
  Dettaglio prenotazione li elenca con link download

Tipi permessi:
  images/*, application/pdf, application/msword,
  application/vnd.openxmlformats-officedocument.*

20. GESTIONE STATO PRENOTAZIONI (DETTAGLIO)
================================================================================

Flusso stati:

  IN_ATTESA  -->  CONFERMATA  -->  COMPLETATA
       |               |
       v               v
  ANNULLATA       RIFIUTATA

  IN_ATTESA:  Prenotazione creata, in attesa di conferma docente
  CONFERMATA: Docente ha accettato
  COMPLETATA: Ricevimento svolto
  ANNULLATA:  Cancellata (da studente o docente)
  RIFIUTATA:  Respinta dal docente

Backend (prenotazioni.service.ts):
  - aggiornaStatoPrenotazione() forza .toUpperCase()
  - Se uno slot viene modificato/eliminato, le prenotazioni associate
    vengono aggiornate automaticamente a ANNULLATA

Frontend:
  - Badge colorati per ogni stato
  - Pulsanti visibili in base allo stato corrente
  - Storico filtra per stato
